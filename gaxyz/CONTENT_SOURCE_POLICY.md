# Content Source Policy

Public claims follow: source → specification → tests → release → public documentation.

1. Product intent may be published as `PLANNED` from approved scope.
2. `IN DEVELOPMENT` requires tracked implementation work.
3. `EXPERIMENTAL` requires runnable artifacts plus limitations.
4. `AVAILABLE` requires a supported release, installation path, release notes, and acceptance evidence.
5. Metrics require a reproducible method and dated source.
6. Security claims require control evidence and owner review.
7. Website review is required when MVP/V1 scope, roadmap, subsystem maturity, VSIX behavior, release status, or security policy changes.

Never publish fake downloads, screenshots, testimonials, user counts, performance figures, or implied network/token availability.
